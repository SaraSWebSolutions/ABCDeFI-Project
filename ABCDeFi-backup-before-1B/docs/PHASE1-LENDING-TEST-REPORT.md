# Phase 1 — Production Lending/P2P test report

**Date:** 2026-08-21  
**Scope:** Phase 1 only: canonical P2P EMI creation, repayment settlement, default/liquidation, frontend chain/ABI configuration, and credential fallback removal.

## Implemented fixes

1. **EMI schedule integration and artifacts**
   - Confirmed the canonical path is `LoanMarketplace -> LoanManager -> EMIManager`.
   - Retained the one-time `setEMIManager()` configuration, the marketplace `EMI_OPERATOR_ROLE` grant, and creation of the schedule immediately after the LoanManager record.
   - Extended `IEMIManager` to include the canonical schedule/default operations and regenerated Hardhat artifacts with `hardhat compile`.
   - Schedule creation now gives the final installment the exact rounding remainder, so the schedule total equals the contractual total.
2. **P2P repayment**
   - `EMIManager.payEMI()` validates the borrower and ACTIVE state, transfers ABCD directly from borrower to the loan's recorded lender, and then records the repayment.
   - No borrower EMI payment is retained by EMIManager.
   - LoanManager uses its fixed EMI schedule total for completion and accepts the final rounding remainder.
3. **P2P default and liquidation**
   - `markDefaulted()` changes an overdue (due date plus 7-day grace) ACTIVE loan to DEFAULTED and emits `EMIDefaulted`.
   - `liquidateDefaultedLoan()` requires DEFAULTED state and transfers the request's recorded ETH collateral to the recorded lender, then records LIQUIDATED state.
   - CollateralVault received a borrower-accounted liquidation method so the borrower ledger is decremented before the ETH transfer.
4. **Frontend blockchain integration**
   - Removed committed address constants from `src/Config/contracts.ts`; addresses are now deployment-environment values and fail fast when absent/invalid.
   - Browser wallet expected chain is derived from `VITE_CHAIN_ID`.
   - Replaced stale P2P transaction wrappers with canonical `depositETH`, `fundLoanRequest`, and `EMIManager.payEMI` calls; failed calls no longer fabricate hashes and explorers are chain-aware.
   - Removed `VITE_ADMIN_PRIVATE_KEY` browser signing. Browser actions use the injected wallet.
   - Cleared stale local address values from `.env.local` and `.env.example`.
5. **Credential/authentication blocker**
   - Removed Sumsub secret fallbacks from `server/index.ts`.
   - Restricts CORS to configured origins, uses constant-time webhook signature comparison, removes seeded demo user and mock JWT issuance, and requires a server-only session signing secret before issuing a session.

## Tests added

`test/P2PLendingIntegration.test.ts` now proves:

- funding creates a populated EMI schedule;
- each schedule payment credits the lender and EMIManager retains no borrower repayment;
- schedule amounts sum to the contractual repayment total;
- non-borrower payment, unauthorized default, liquidation before default, and default before grace fail;
- after the grace period, a loan transitions ACTIVE -> DEFAULTED -> LIQUIDATED and recorded collateral reaches the lender exactly once.
